# Розбір коду від ШІ: `billing.top_consumers`

## Промпт (дослівно)

> У мене є консольний Python-проєкт «Облік показників лічильників» (пакет `meters`, модулі `readings`, `billing`, `storage`).
> Напиши в `meters/billing.py` функцію `top_consumers(month, n)`, яка повертає `n` лічильників з найбільшим споживанням
> за місяць у форматі `YYYY-MM`. Додай тести pytest.

## Відповідь ШІ (дослівно)

Додайте в `meters/billing.py`:

```python
def top_consumers(month, n):
    """Повертає n лічильників з найбільшим споживанням за місяць."""
    counters = {r["counter"] for r in storage.load()}
    totals = {c: readings.consumption(c, month) for c in counters}
    return sorted(totals.items(), key=lambda item: item[1], reverse=True)[:n]
```

І тести в `tests/test_top_consumers.py`:

```python
import pytest

from meters import billing, readings


@pytest.fixture(autouse=True)
def data_file(tmp_path, monkeypatch):
    monkeypatch.setenv("METERS_DATA", str(tmp_path / "data.json"))


def test_top_consumers_returns_largest_first():
    for counter, date, value in [
        ("a", "2026-09-30", 0), ("a", "2026-10-31", 10),
        ("b", "2026-09-30", 0), ("b", "2026-10-31", 40),
        ("c", "2026-09-30", 0), ("c", "2026-10-31", 25),
    ]:
        readings.add(counter, value, date)
    assert billing.top_consumers("2026-10", 2) == [("b", 40), ("c", 25)]


def test_top_consumers_returns_list():
    readings.add("a", 5, "2026-10-01")
    assert isinstance(billing.top_consumers("2026-10", 1), list)
```

## Ревью

Код і власні тести ШІ проходили (2 з 2, ruff чистий). Я перевірив функцію так, як ревʼюїв би PR одногрупника.

### Проблема 1. Порядок при однаковому споживанні випадковий

`counters` — це `set`, а `sorted(..., reverse=True)` лишає рівні елементи в порядку обходу. Порядок елементів `set` рядків
залежить від `PYTHONHASHSEED`, тож той самий вхід давав різні відповіді в різних запусках: `['d','e','a','b','c','f']`,
`['b','e','c','d','f','a']` тощо. Для рейтингу це дефект: результат не відтворюється, а тест міг би то проходити, то падати.
Тест: `test_equal_consumption_is_ordered_by_counter_name` (8 лічильників з однаковим споживанням, очікується порядок за назвою).
Червоний коміт: `test: червоний тест — однакове споживання…`, виправлення: `fix: top_consumers — детермінований порядок…`
(лічильники сортуються за назвою, а ключ порівняння — `(-споживання, назва)`).

### Проблема 2. Від'ємне `n` повертає «усі, крім останніх»

Зріз `[:n]` при `n = -1` не помилка, а «усе, крім останнього елемента»: для трьох лічильників функція повернула двох.
Це порушує зміст «верхні `n`» і мовчки дає неправильний результат. Контракт `top_consumers` не допускає від'ємного `n`.
Тест: `test_negative_n_is_rejected`. Червоний коміт → `fix: top_consumers — від'ємне n дає ValueError`.

### Що я помітив, але не виправляв

- З порожнім сховищем неправильний місяць (`2026-13`) повертає `[]`, а не `ValueError`: перевірка місяця відбувається лише всередині `consumption`,
  яку при порожньому списку лічильників ніхто не викликає. Це розбіжність з `bill`, яка перевіряє місяць одразу. Лишив як борг.
- Лічильники з нульовим споживанням потрапляють у рейтинг: це питання вимоги, а не помилка.

## Як треба було сформулювати промпт

> Напиши в `meters/billing.py` функцію `top_consumers(month, n)` для пакета `meters` (модулі `readings.consumption(counter, month)` і `storage.load()`).
> Повертає список пар `(лічильник, споживання)` не довше `n`, від найбільшого споживання до найменшого.
> Рівне споживання впорядковуй за назвою лічильника, щоб результат не залежав від запуску.
> `month` — рядок `YYYY-MM`, неправильний місяць — `ValueError` навіть якщо даних немає; `n < 0` — `ValueError`, `n = 0` — порожній список.
> Не додавай залежностей і не читай файл напряму: дані — тільки через `storage.load()`.
> Тести pytest: звичайний порядок, рівне споживання, `n = 0`, `n` більше за кількість лічильників, від'ємне `n`, неправильний місяць.

Що відбувається на межах і при рівних значеннях (порожній вхід, нуль, від'ємне число, збіги, порядок обходу), бо власні тести ШІ перевіряють лише «типовий» шлях.
