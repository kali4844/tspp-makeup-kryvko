# Постмортем 1. Занижене споживання, якщо показник внесли «заднім числом»

Версія з дефектом: `v0.1.0`. Виправлення: `v0.1.1` (гілка `hotfix/readings-out-of-order`, злита з `--no-ff`).
Інцидент змодельований на тестових даних; сценарій відтворюється за кроками нижче.

## Що сталося

Показник за 10 жовтня було внесено вже після показника за 31 жовтня (мешканець знайшов забутий запис).
Команда `consumption water-1 2026-10` повернула `30.0` замість `60.0`, а `bill 2026-10 2.5` — `75.0` замість `150.0`:
рахунок за жовтень вийшов удвічі меншим за справжній.

Кроки для відтворення на `v0.1.0`:

    python -m meters add water-1 1000 2026-09-30
    python -m meters add water-1 1060 2026-10-31
    python -m meters add water-1 1030 2026-10-10     # внесено пізніше, дата раніша
    python -m meters consumption water-1 2026-10     # очікували 60.0, отримали 30.0

## Як помітили

Рядок журналу (рівень INFO) показав, які саме показники пішли в розрахунок:

    INFO meters.readings consumption result: counter=water-1 month=2026-10 base_date=2026-09-30 last_date=2026-10-10 result=30.0

`last_date=2026-10-10`, хоча в даних за жовтень є показник за `2026-10-31`. «Останнім» узято не найпізніший за датою, а останній за порядком внесення.
Без цього рядка з виводу `30.0` причину не було б видно: число виглядає правдоподібно.

## Вплив на користувача

- Занижена сума до сплати (у прикладі вдвічі). Недоплата вийшла б боргом на наступний місяць, який користувач не очікує.
- `anomalies` у такому випадку видає хибну аномалію («значення менше попереднього») на повністю коректних даних.

## Причина

`storage.load()` повертав записи в порядку внесення, а `readings.consumption` вважала «останнім» показником місяця останній елемент у списку.
Припущення «показники вносять за зростанням дат» ніде не було ні записане, ні перевірене тестом: усі тести вносили показники по порядку.

## Що змінили, щоб не повторилось

- `storage.load()` повертає записи, впорядковані за датою (стабільне сортування: однакові дати лишаються в порядку внесення). Виправлення в одному місці, тому воно діє і на `consumption`, і на `anomalies`.
- Тест, що відтворює дефект, `test_reading_added_later_with_earlier_date_does_not_break_consumption`, — окремим комітом, червоним до правки.
- Запис у `CHANGELOG.md` і тег `v0.1.1`.
- Не змінювали: поведінку при двох показниках з однаковою датою (береться той, що внесено пізніше) — це лишається відкритим питанням для наступної версії.
