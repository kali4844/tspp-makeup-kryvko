# Тест-кейси: `readings.consumption` і `readings.add`

Найризикованіша функція продукту — `readings.consumption(counter, month)`: від неї залежить сума в `billing.bill`,
а помилка в споживанні виглядає як правдоподібне число, тож її помітять останньою (коли абонент отримає рахунок).

Очікувані результати записано **до** запуску коду. Усі дати — у форматі `YYYY-MM-DD`, лічильник — `m1`.

| №  | Вхід (показники у файлі → виклик)                                              | Клас / межа                              | Очікуваний результат   |
|----|---------------------------------------------------------------------------------|------------------------------------------|------------------------|
| R1 | `2026-10-15 = 100` → `consumption("m1", "2026-10")`                             | межа: єдиний показник у місяці           | `0`                    |
| R2 | `2026-10-05 = 100`, `2026-10-25 = 130` → `consumption("m1", "2026-10")`         | еквівалентність: два показники в місяці  | `30`                   |
| R3 | `2026-09-30 = 100`, `2026-10-10 = 120` → `consumption("m1", "2026-10")`         | межа: база — останній день попер. місяця | `20`                   |
| R4 | `2026-09-30 = 100`, `2026-10-31 = 140`, `2026-11-01 = 150` → `consumption("m1", "2026-10")` | межа: 1-ше число наступного місяця не входить | `40`        |
| R5 | `consumption("m1", "2026-13")`                                                  | недійсний вхід: неіснуючий місяць        | `ValueError`           |
| R6 | `add("m1", -5, "2026-10-01")`                                                   | недійсний вхід: від'ємне значення        | `ValueError` (TDD)     |

Межові: R1, R3, R4. Недійсні: R5, R6.

R1–R5 покриті тестами в `tests/test_readings.py`. R6 — поведінка, якої на момент складання таблиці ще немає: тест червоний
окремим комітом, потім коміт з правкою `readings.add` (TDD).
